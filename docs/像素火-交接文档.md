## 二、踩过的坑与**定论**（每条都有实测依据，别重走）

### 1. ★★★ 文本框 `text` 有**长度上限** —— 这是最大的坑
- 现象：屏幕**显示原始标签文字**（`<color=#…>■</color>`）而不是彩色图形；且**看似随机地闪**。
- 真因：**引擎日志原文**：`#spike:211: 文本长度超出限制`
  - 引擎只记日志，**`pcall` 不抛错** ⇒ 脚本侧 `fails=0` 会骗人 ✗
  - 实测：串 ~1500 字符 ✓ 能显示；~2485 / ~2683 ✗ 超限
- 对策：**分块**（我们分 3 条行带，每带 9 行 × 16 列 ≈ 300~900 字符 ✓）
- 参考：官方社区工具 `ImageToRichTextConverter` README：**按字符分段（默认每段 1000 字符），避免超出平台限制** ✓（本地已 clone：`D:\train\tools\irt\main.py`）

### 2. 像素字形 = `█`（U+2588 全角实心块）
- 候选对比实测：`█` 最满；`▉▊▋▌▍■◼▮●` 都比它**窄** ✗ ⇒ **不要换字形**
- 透明格两种写法（官方工具用的）：
  - `<color=#RRGGBBAA>` 且 **A=00**（`#00000000`）✓ ← 我们用的
  - **全角空格 `　`（U+3000）** ✓（`main.py:304`）—— 半角空格会被裁 ⇒ **不要用** ✗

### 3. `<size>` **不能用来放大像素** ✗
- 它会把平台**行距**一起撑大 ⇒ 网格变松 ⇒ 画面变成"稀疏横条" ✗
- 要放大像素：**直接调控件 `fontSize`（脚本里的 `FONT`）** ✓

### 4. `localScaleX/Y` 也没有用 ✗
- 它缩放**整个控件**（字与缝一起缩）⇒ 比例不变 ⇒ 缝不会消失 ✓

### 5. 设计坐标空间 = **1600×900**（用户提供）
- 运行时 `game.GetUICanvasSize()` 实测 **1680.8×900** ⇒ 缩放 **1.05** ✓
- ⇒ 所有像素测量要**除以 1.05** 换回设计像素 ✓
- 实测**行距 = 0.90 × 字号**（设计像素）⇒ 带步进 `step = 9 × FONT × 0.90` ✓

### 6. 其他已确认的平台事实
- 锚点/轴心是**字段**（`c.anchorMinX = 0` ✓）；位置/尺寸是**方法**（`SetAnchoredPosition` / `SetSizeDelta`）✓
- **不存在** `SetAnchorMin/SetAnchorMax/SetPivot` 方法 ✗（用了会静默失败）
- 颜色：`Color.FromRGBA(r,g,b,a)` ✓
- 文本框模板索引（本关卡实测）：**文本框 `1073741850`** ✓ / 图片 `1073741851` ✓ / 光标区 `1073741852` ✓
- 对齐必须**显式设置**：`c.horizontalAlignment = Enum.TextHorizontalAlignment.Middle` ✓
- 框高 `bh` **只是裁剪矩形** ⇒ 给足余量（我们用 2×）⇒ 内容不会被裁 ✓；真正决定排版的是**带步进 step** ✓

### 7. 部署链路（另一个大坑）
- **关卡里存的是"导入那一刻的副本"** ✗ ⇒ 只改 `external_lua_file\spike.lua` **不生效**，必须在编辑器里**重新导入** ✓

## 三、当前实现（`fire_v52.lua`）参数一览

```lua
local FONT = 44            -- 字号（像素大小就是它；不要用 <size> ✗）
local SIZE_K = 1.00        -- 1.00 = 不用 <size>
local BANDS = 3            -- 分 3 条行带（每带 9 行）⇒ 绕开文本长度上限 ✓
local STEP 系数 = 0.90     -- step = 9 × FONT × 0.90（实测行距系数 ✓）
bh = 9 × FONT × SIZE_K × 2 + 8   -- 框高给 2 倍余量（只是裁剪矩形 ✓）
冷端 = <color=#00000000>█</color>（透明 ✓ 无黑条 ✓）
对齐 = Middle（水平）/ Top（垂直，避免裁切 ✓）
居中 = 按 (BANDS-1)×step + bh 算 ✓
动画 = 20fps（每 3 帧重算）✓；脏检查（串变了才写）✓
```

## 四、✗ 唯一未解决：格子间 5~7% 的细缝

- 实测：FONT=44 时格 ≈55px、缝 ≈2~4px；字号 20→32→44 **比例几乎不变** ✗
- ⇒ 这是**字体固有的是 side bearing**（字形内边距）✓，脚本层无解 ✗（换字形/`<size>`/`localScale` 全部试过 ✓ 见 §二）
- **⇒ 唯一能保证无缝的方案：像素改用「图片控件」** ✓✓
  - 每个像素 = 一个图片控件（素材 `100001` 方块，你们实测"拉长不糊" ✓ + `imageColor` 上色 ✓）
  - 没有字形内边距 ⇒ 想多大就多大 ⇒ 严丝合缝 ✓✓
  - 成本：**8×14 = 112 个控件** ✓✓（推荐先做）；16×27 = 432 个 ✓（上限 1000，也够 ✓）
  - 动画：脏检查写 `imageColor`（只写变化的格 ✓ 每帧约 30~50 次 ✓ 祖玛真机跑过 900+ 控件 ✓）
