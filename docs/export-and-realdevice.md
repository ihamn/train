# 导出物与真机验证流程（步骤 7）

## 1. 导出物在哪

`workspace/train/export/`（由 `tools/export_gia.mjs` 生成，可随时重跑）

| 文件 | 大小 | 内容 | 用途 |
|---|---|---|---|
| `列车 M0 探针 · 整合包.gia` | 21.3 KB | 服务端 `UIControlGroup` + 客户端 `UIControlTemplate` 并排在同一 `Root.graph`，脚本源码与**控件挂载**一起带走 | **推荐导入千星用这个** |
| `列车 M0 探针 · 服务器控件模板.gia` | 14.2 KB | 只含控制类资产（20 个控件），不含脚本源码 | 想单独看/替换 UI 时用 |
| `列车 M0 探针 · 脚本.gia` | 3.4 KB | 只含 Lua 脚本源码（不带挂载） | 脚本单独导入时用 |
| `export-report.json` | 4.7 KB | 导出清单、警告、往返校验结果 | 存档凭据 |

重新生成（改完布局或脚本后）：

```bash
cd D:/train
QXQY_STUDIO="D:/miliastra-beyond-simulator/studio/index.js" node tools/export_gia.mjs
```

**为什么不是顶栏「导出」按钮**：顶栏导出是人工 UI 动作，我这边没有导出工具。
本脚本调的是模拟器自己的 GIA 编解码器（`studio/index.js` 的 `exportData`），出的是同一批格式，
额外好处是能在同一进程里把导出的 GIA **再导入回来比对**（见 §3）。

## 1.5 v5 起：**不再需要导入 GIA**（重要，先读这段）

工程在 v5 换成了**本工程 zuma 已验证的真机架构**：界面布局里不摆具名控件，
所有控件由 `spike.lua` 在 `OnStart` 里 `game.InstantiateClientUIControl(模板索引, 父控件)` 建出来。
真机因此只需要三样，**GIA 导入变成可选项**（那份预填控件组反而会和运行时建的撞名）：

| # | 在千星里做什么 | 为什么 |
|---|---|---|
| 1 | 界面控件组库 → **客户端控件模板**：添加一个**图片**控件、一个**文本框**控件，各**存为模板** | 运行时建控件必须有可实例化的单控件模板；脚本会自己认索引，**不用抄数字** |
| 2 | 界面控件组管理 → **界面布局**：放一个**客户端控件容器**，勾**初始可见** | 官方规则：客户端控件必须依托容器，且容器"激活+可见"时客户端控件与脚本才生效 |
| 3 | 客户端脚本资源管理器 → **新建脚本映射**，名字用**平铺**的 `spike.lua`（**不能带斜杠**），关联本地 `D:\train\workspace\train\spike.lua`，并把脚本挂到容器上 | 带目录的映射名是模拟器 `require` 的"导入根"约定，千星真机不接受 |

然后：**保存关卡 → 试玩**。两处证据我这边自动收：
* 客户端脚本日志 dump：`BeyondLocal\<UID>\Beyond_Debug_Log\*.gia`（`tools/watch-realdevice.ps1` 自动解码成文本）
* 试玩画面：同一脚本检测到 `isTrial:True` 会自动连拍原神窗口

> ⚠️ 挂载点（客户端控件容器）**尺寸不能是 0×0**，否则子控件被整体裁掉 ——
> 表现就是"脚本全跑通、屏幕全空"。脚本会自己 `SetSizeDelta(画布宽, 画布高)` 兜底，
> 但编辑器里也别留 0×0。
>
> ⚠️ 运行时几何约定（真机 zuma.lua 已证）：`SetAnchoredPosition` 相对**父矩形左下角**，
> 等价于"以画布中心为原点"。脚本已把每个控件的锚点/中心显式钉成 (0,0)，不依赖模板默认值。

## 2. 导进千星（人工动作，v5 起可跳过）

1. 打开千星沙箱 → 界面控件组管理 → 导入 → 选 `列车 M0 探针 · 整合包.gia`
2. 导入后确认：`UI控件-服务端` 里出现「客户端控件容器 → STAGE」+ 19 个子控件；
   `UI控件-客户端` 出现「Lua实例化面板」（未改动的出厂模板，可以不管）
3. **建立脚本映射**：客户端脚本资源管理器 → 脚本映射 → 路径设为 `workspace/train/spike.lua`，
   关联本地文件 `D:\train\workspace\train\spike.lua`
4. 把脚本挂到 `STAGE` 控件（脚本页签 → 添加脚本）；GIA 的整合包已带挂载关系，
   若导入后挂载丢失，手动挂一次
5. 试玩，按 §4 的四条逐项看，把结果（截图/文字）回传

> ⚠️ 脚本映射的本地文件必须真的存在，否则运行时不会打包上传。
> 本机 `qxqy_script_sync` 尚未配置（`status: {config: null}`，`discover: candidates: []`），
> 如果你的千星客户端脚本目录不在本机，第 3 步手动做即可。

## 3. 已做的模拟器侧往返校验

`tools/export_gia.mjs` 把导出物重新导入到一台全新 studio，比对结果：

| 导出物 | 往返结果 |
|---|---|
| 服务器控件模板.gia | 控件名 20/20，`missing: []`，`extra: []` |
| 脚本.gia | 路径 `workspace/train/spike.lua`、源码逐字节一致（挂载不带，符合预期） |
| 整合包.gia | 控件名 20/20；脚本路径/源码一致；**挂载保留** `controlId: n1` / `controlAsset: server-control-template` |

导出时模拟器给出的警告（**要一并当真机待验项**）：

* `HUD: 垂直居中按推定值导出，尚待实机确认。` ← 文本垂直居中的 GIA 取值 1 是推断值
* `新服务端控件模板写入显式空 Info.related，避免跨沙箱复用伴生资源 GUID 产生无法加载的索引。`
* `GIA 导入为已验证 UI 字段的语义导入；未知 protobuf 字段不会进入 Authoring JSON。`

以上都只证明**模拟器的编解码自洽**，不代表真机导入成功。

## 4. 真机上要看什么（照着做，逐条回传）

| # | 动作 | 记录什么 |
|---|---|---|
| R1 | 试玩，看列车是否每 ~0.12 秒换一个图元、HUD 帧号是否跟着走 | 截图 + HUD 显示的帧号 |
| R2 | 看列车是否真的在往右移动、车厢是否在变宽 | 截图（两张不同时刻） |
| R3 | **前提③**：摆一个 3D 实体 + 运动器让它沿轨移动 | 能动/不能动，用了什么节点 |
| R4 | **前提④**：把 STAGE 这层 UI 叠在 3D 画面上 | 能否叠加、是否被裁切 |
| R5 | 顶点/控件预算：这套 20 控件是否触碰上限；文本像素方案实际顶点数 | 编辑器报数或报错原文 |
| R6 | HUD 文本的垂直居中是否如预期 | 截图 |

R1/R2 是模拟器已经证明成立的项，真机只需确认**行为一致**；
R3/R4 是模拟器测不了、只有真机能回答的项，**它们决定动画路线 A/B 的取舍**（见 `docs/production-plan.md`）。
