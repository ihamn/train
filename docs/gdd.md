## 1. 一句话

2.5D 等距视角的像素风列车游戏：**用档位把速度维持在限速区间里，换挡会累积轴温，轴温满了被迫停车**。

## 2. 核心循环

```
读限速区间 → 判断该升速还是掉速 → 换一档 → 承担轴温代价 → 维持住 → 按"合规行驶的距离"持续得分
                                          ↑                                    ↓
                                     轴温随时间冷却 ←──────── 不换挡就没有代价 ←┘
```

* 玩家唯一的主导权是**档位**；环境（上坡/下坡/弯道）是不受控的外部变量。
* 得分是**保持**型（连续梯度），不是达成型（0/1）。
* 惩罚的是**动作**（换挡）而不是**状态**（速度慢）⇒ 允许"想清楚再动"。

## 3. 操作

| 输入 | 行为 |
|---|---|
| 升档 / 降档 | 改变档位（7 档，−3 ~ +3，0 为空档） |
| （停靠段）停车 | 把列车停在横条范围内 |

PC 用键鼠（奇匠按键），手机用触屏按钮——**同一套 UI 控件，两种输入设备**，
按键监听走 `AddKeyEventListener`，触屏走预设按钮的光标事件。

## 4. 胜负与计分

| 系统 | 职责 |
|---|---|
| 限速区间 | 主要得分来源（保持速度 = 持续得分，漏分不倒扣） |
| 停靠对位 | 第二得分来源（一个位置差 → 一个分数） |
| 轴温 | 惩罚动作，满了扣分 + 档位锁 0，直到冷却归零 |
| 副维度（待定） | 千星没有好友排行榜 API，原作的"时间做第二标准"搬不过来，需要一个替代副维度 |

**没有失败态**：轴温满只造成"惩罚性停顿"，不是 game over。关卡以"跑完全程"结束。

## 5. 千星可行性（已核实 / 待核实）

| 机制 | 千星 | 依据 |
|---|---|---|
| 档位 + 速度色 + 限速区间 | ✅ 纯标量比较，极省控件 | `列车小游戏_设计拆解.md` §四 |
| 停靠对位 | ✅ 一个位置差 → 一个分数 | 同上 |
| 轴温计数器 + 冷却 | ✅ 一个整数 + 计时 | 同上 |
| 好友排行榜 / 时间做第二标准 | ❌ 无排行榜 API | 同上 |
| 逐帧换图做动画 | ✅ **模拟器 + 真机均已验证** | `docs/tests-m0.md` / `records/playtest.md` |
| 界面控件运行时移动/改大小 | ✅ **模拟器 + 真机均已验证**（方法式 `SetAnchoredPosition`/`SetSizeDelta` 真机写回逐帧一致）；原仓库记录说"不能"，已作废 | 同上 |
| 3D 实体沿运动器移动 | **不适用 / 已移除** —— 本工程是**全 UI 控件**实现（2D+Lua），不用 3D 实体，也没有运动器这条路线（用户 2026-10-07 明确澄清） | 用户澄清 |
| 控件叠在游戏画面上 | **真机成立（叠加本身）／范围未解** —— 客户端 UI 确实画在关卡画面上，但只盖住左下角，裁定为**挂载点几何**问题，待只读探针取证 | `records/playtest.md` 真机第五/六轮 |

## 6. P0 范围（M1 起步，最小可玩）

1. 一条轨道 + 一列车沿轨移动（视觉上成立即可，不追求 2.5D 等距）
2. 档位操作（升/降）+ 速度读数
3. 限速区间 + 保持得分
4. 轴温：换挡累积、时间冷却、满了锁档
5. 一关跑完 + 结算分数

**不在 P0**：多关卡、封面、排行榜替代副维度、2.5D 等距美术、文本像素轨道。
