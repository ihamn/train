# 列车 Lua v1：玩法已移植，千星美术与真机接线待验

2026-10-11。此版是网页规则的可执行 Lua 移植，包含试行关和站间无尽模式；不是官方源码，也不是已经完成真机导入的关卡。无尽每站四段限速，普通低→中→高→低，每四站一次低→高→中→低的下坡组合。每站新建路线，累计分数/里程/热量保留，只保存当前站的数据。

## 文件与运行

| 文件 | 用途 |
|---|---|
| `workspace/train/train_core.lua` | 纯玩法模块；标准 Lua `dofile` / `require` 可运行，无引擎依赖 |
| `workspace/train/train_client.template.lua` | 千星客户端接线模板，不能直接挂载（内有核心占位符） |
| `workspace/train/train_game.lua` | **挂载用单文件**，已内联核心，不依赖千星 `require` 路径 |
| `tools/build-train-lua.mjs` | 编辑核心或模板后，重新生成挂载文件 |
| `tests/lua-train.test.cjs` | 对照 JS 路线与整趟驾驶输入、Lua 边界检查、接线 mock |

```sh
node tools/build-train-lua.mjs
LUA=/你的/lua/路径 node --test tests/*.test.cjs
# LUA 不指定时使用 PATH 中的 lua（测试至少需 Lua 5.3）
lua tests/lua-train-checks.lua
```

纯模块示例：

```lua
local Train = dofile('workspace/train/train_core.lua')
local s = Train.createState({mode='endless', seed=42})
Train.start(s)
Train.shift(s, 1) -- 只允许逐档换；不会绕过温度
Train.update(s, 1/30)
local ui = Train.view(s)
-- 到站 s.phase == 'finished' 后：Train.continueJourney(s)
-- 暂停/结束：Train.pause(s)、Train.endJourney(s)
```

`start` 重开第 1 站、清空累计；`continueJourney` 才保留累计。`endJourney` 不凭空发停车奖励。模式只能在准备/结算界面切换。没有自动驾驶，测试中的参考驾驶器不进入客户端脚本。

## 与网页一致的规则

- 档位 −3..3 的力为 −6、−5、−4、−1、2、3、4，与环境力叠加。无路段限速时仍能换档，车辆物理上限 120 km/h。
- 表盘 180° 对应 0..120。蓝区 0..53 的速度响应为净力×4 km/h/s，其余为×8；净力 ±0.5 在非蓝区对应 ±6°/s。蓝区净力 ±1 对应相同偏转速度。蓝区对称处理是项目规则，来源说明见仪表文档。
- 温度是 0..1 的热量，**210° 是总扫角，不是 210 摄氏度**。每次有效换档 +25%，每秒降 5%；满热强制空档冷却 3 秒，最多扣当前已有的 200 分，分数下限 0。
- 过渡环境使用 smoothstep，坡度画面使用同一环境函数的积分。普通距离分按每 5m 结算，结束补齐尾数；限速段全程合规奖励 +100，精确检查段界的瞬时速度，违规一次取消该奖励。
- 最后 300m 不限速，前 200m 渐变回平地，最后 100m 平地停车提示；站心 ±5m 根据误差给最多 200 分，超过站心 35m 结算错过停靠。
- 子步 1/120 秒。速度单位是 km/h，移动距离除以 3.6；不会用档位动画伪装速度变化。

## 千星编辑器接线

在独立、可移除的客户端控件容器中预先布局。将 `train_game.lua` 映射为**平铺名字 `train_game.lua`**并挂载；保存关卡才能重新打包生效。此版不覆盖历史 `train.save.json` / M0 GIA，它们仍是旧探针，不能当成此次游戏的完整导入包。

本脚本只查固定名字，不扫描模板、不动态实例化、不修改 `script.object` 的几何。适配父容器的裁切/原点必须在编辑器完成。所有数字尺寸是容器的设计坐标，手机不同画布通过父层统一适配。

| 名称/路径 | 类型与布局 |
|---|---|
| `SPEED`, `GEAR`, `TEMP`, `SCORE`, `TARGET`, `STATUS`, `HINT` | 文本框；必需。`TARGET` 摆在速度仪表盘上方；`HINT` 在仪表盘上方的提示带 |
| `START`, `UP`, `DOWN` | 可接收点击的控件；必需，分别重开、升档、降档 |
| `PAUSE`, `CONTINUE`, `END`, `TRIAL`, `ENDLESS` | 完整交互应建齐；暂停/继续驾驶、到站续行、结束旅程、选择模式 |
| `HINT_BG` | 普通图片，提示颜色由 `.imageColor` 更新；不支持向文本框写图片颜色 |
| `PROGRESS/SEG1`..`SEG11` | 顶部进度条内的普通图片；父容器宽 600、高 12；点锚在左下、pivot 左下。只有限速段显示，间隔保持空白 |
| `PROGRESS/PROGRESS_MARKER` | 当前里程游标，同父容器，Y=20 |
| `DIAL/TARGET_RANGE` | 可选直线目标范围；父容器宽 240、pivot 左下；与仪表盘同标定。它是直线版本，尚未导入网页的金色弧形目标环 |
| `SPEED_F0`..`SPEED_F36` | 可选速度指针预制帧，每帧 5°，叠在同一仪表盘位置，统一中心；背景盘不要放进针帧 |
| `TEMP_F0`..`TEMP_F42` | 可选温度指针帧，每帧 5°，总 210°；同上 |
| `SCENE/TIE1`..`TIE4` | 可选四个轨面标记。场景宽 720，车固定在 (240,0)；地面标记按实际路程向左移动，Y 来自坡度积分 |

未建可选项时数字玩法仍可运行；要验收完整 UI，必须补齐相应控件和美术。**本次没有生成新的千星文字像素车/轨道/针帧资源**。车头需把既有定稿美术预先朝右摆放；网页 PNG 不能视为千星可上传的自定义贴图。四个地面标记只是验证位移与坡度的接线样例，完整轨道仍需美术实现。

用到的 API 是仓库已有例子的 `FindChild`、`SetAnchoredPosition`、`SetSizeDelta`、`SetActive`、`.text`、`.imageColor`、`AddCursorEventListener(Enum.CursorEventType.CursorClick, ...)`、`script:EnableUpdate`。没有假设 `OnButtonClick`、通用 `KeyDown` 或自定义指针旋转属性。路径查找、图片颜色、控件事件与文本动态更新的组合仍需该关卡真机核对。

UI 每 0.2 秒尝试更新一次，并对文本、整数位置、尺寸、显隐、颜色做脏检查。动画是此首版的 5Hz 接线验证，尚未承诺网页的流畅度。API 调用首次失败立即停更并仅记录一次错误；超过 0.5 秒的帧卡顿暂停驾驶，防止同步补算占满回调。玩家点击恢复后继续，不把漏掉的时间偷偷计入行驶。

## 已验证与尚未验证

Lua 5.3.6 实际执行通过：128 种种子/站号组合的每段路线与 JS 一致；试行、普通无尽、下坡无尽、较后站次以相同玩家换档输入运行，逐秒比较速度/距离/热量/时间/分数/合规距离/档位/过热/完美段数/阶段一致。另验证零分过热、蓝区响应、封顶、210°温度、24 次续行、奖励只发一次和客户端 mock 点击/暂停/错误停更。整个仓库模型测试 36 项通过。

这证明玩法移植与理论路线可执行。接线 mock 不验证千星原生 API，也不验证手机触摸、美术、GIA 导入或真实控件裁切。下一步是在编辑器按上述表建最小控件容器，导入单文件，先验出发/换档/计分/到站续行，再补完整美术。
