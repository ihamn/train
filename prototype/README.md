# 至冬列车 · M1 效果展示（HTML 小样）

> 这一步（七步工作流的**步骤 3**）的作用：**在你投入 Lua 之前，先让你用手感判断"好不好玩"**。
> 它不是游戏本体，也不是要交给千星的代码 —— 千星那边是 Lua + 控件，两边坐标习惯也不同（见下）。

## 怎么打开

**双击 `prototype/index.html`** 就行（纯 HTML/JS，无依赖、不联网、不需要服务器）。
出问题时也可以右键 → 打开方式 → Chrome / Edge。

## 怎么玩

| 操作 | 键 |
|---|---|
| 升档 / 降档 | `↑` / `W` 升，`↓` / `S` 降（也可点画面底部两个按钮） |
| 重开 | `R` |
| 拖动滑块 | 右下角四个：换挡升温 / 冷却速度 / 牵引加速度 / 限速带宽度 |

**核心循环**：读限速区间 → 判断该升还是该降 → 换一档（**承担轴温代价**）→ 维持住 → 持续得分。
**没有 game over**：轴温满只是"被迫空档冷却"的惩罚性停顿。

## 这一版覆盖了什么

* **开局**：说明 + 开始按钮
* **第一次成功**：第一次把速度压进限速带时会有提示（这是"学会了"的一刻）
* **失败（惩罚）**：轴温满 ⇒ 档位锁 0、强制冷却、红字提示
* **重开**：`R` 或结束页按钮；结束页显示得分与"被锁档次数"
* **两个得分来源**：合规行驶（持续）+ 停靠对位（一次性）

## 需要你反馈的三件事（这就是做这一版的目的）

1. **节奏对不对**：限速带该宽还是该窄？现在默认 24 km/h（滑块可调）
2. **代价疼不疼**：换挡的轴温代价 —— 仓库里有两种说法（**1/3：3 次满** 与 **1/4：4 次满**），
   右下角两个预设按钮可以一键对比 ⇒ 你玩完告诉我哪个更对（这条会写回策划案）
3. **有没有"想再来一次"的冲动**：如果无聊，是哪里无聊（等太久？判断太简单？提示不清？）

## 不可移植项（给后面写 Lua 的人看）

| HTML 里的做法 | 千星里要换成什么 |
|---|---|
| `<canvas>` 逐帧重绘整列画面 | 客户端控件（图片/文本框）拼出来，**位置用 `SetAnchoredPosition` 写** |
| CSS 坐标：**左上原点、Y 向下** | 千星：**左下原点、Y 向上** ⇒ 所有 y 要翻（`y_qxqy = 画布高 − y_html`） |
| 键盘事件 `keydown` | `AddKeyEventListener(Enum.KeyEventType["Keyboard…"])`（逐键成员名） |
| 右下角滑块实时调参 | **脚本变量**（`script:GetParam`）⇒ 进游戏前在编辑器里设 |
| 文字直接 `fillText` | **文本框控件**（每行一个控件 ⇒ 行距可控；文本框没有行间距参数） |
| 按钮上的 ▲▲ / ▼▼ | 图片素材号 **100148**（双上箭头）/ **100147**（双下箭头） |
| 进度条 | 底板素材 **106091~106094**（细长条）+ `imageColor` 染色 |

## 与千星的"同一套数值"约定

HTML 里这些数（换挡升温、冷却、加速度、限速带宽度）**直接对应策划案里的可调参数** ✔ ——
所以你在小样上试出来的手感，可以原样搬到 Lua 里；这也是为什么这一版把滑块做得这么显眼。
